# C 포트 상태

## 현재 플레이 범위

메뉴에서 1인, 2인 협동 플레이 또는 순위표를 선택합니다. 초록 1P와 파랑 2P는 각자의 키보드 배치와 게임패드로 이동, 점프하고 거품을 발사합니다. 2인 모드에서 2P 발사는 Right Shift입니다. [참고 저장소 main의 커밋 `5ea6398`](https://github.com/luvxxxu/BubbleBobble/tree/5ea63987d393d9f3c811a5b129f453d08e599bd0)을 기준으로 다음 규칙을 복원했습니다.

- ZenChan·Maita·Monsta의 이동과 공격, 거품 포획·탈출·처치, Maita의 바위 투척.
- 서로 다른 다섯 라운드와 라운드별 1·2·3·4·5마리의 적, 7초 클리어 대기와 최종 승리.
- 음식 20종의 드롭과 습득 점수, 플레이어별 생명 5개, 사망·부활·무적, 전원 탈락 시 게임 오버.
- 플레이어별 이니셜 입력과 상위 10개 기록의 저장·표시. 저장 실패 재시도와 기존 파일 보호.

각 라운드는 공중 발판 다섯 개, 측면 벽과 바닥 순환 통로를 갖습니다. 다른 플레이어가 포획한 적도 터뜨릴 수 있으며, 음식 점수는 실제로 먹은 한 사람만 받습니다. 한 사람이 탈락해도 남은 사람이 계속합니다. 원본 아트는 보존합니다.

각 플레이어의 마나는 15초 충전과 5초 가속을 반복합니다. 저장 상태와 계산이 독립적이며, 1인 모드의 2P는 갱신하지 않습니다. 게임을 새로 시작하면 두 사람의 마나와 발사 대기시간, 거품을 초기화합니다. 메뉴·인트로·결과 화면·사망 대기·탈락·일시 정지·창 포커스 상실 중에는 마나가 진행되지 않습니다. 부활이나 다음 라운드에서는 남은 마나와 점수를 유지합니다.

## 코드 구조

게임 로직은 고정 배열, 간단한 구조체, 일반 함수, 조건문과 반복문으로 구성합니다. 충돌 백엔드 함수 포인터와 이벤트 비트마스크를 제거했습니다. `bb_game_update` 한 번으로 플레이어, 적, 거품, 바위, 아이템, 접촉 판정과 진행 상태를 순서대로 처리하므로 호출자가 별도 충돌 함수를 호출할 필요가 없습니다. 마나는 `update_mana`에서 한 사람씩 계산하고, 충돌과 소리 발생 여부는 이름이 있는 참/거짓 필드로 표시합니다.

그래픽·입력·소리는 Raylib 5.5를 계속 사용합니다. 게임 규칙의 회귀 테스트는 창 없이 실행됩니다. 고정 시간 갱신, 배열 범위 검사, UTF-8 경로 처리와 자원 정리는 유지합니다. 게임 규칙에는 동적 메모리 할당이 없습니다.

## 검증 범위

2026-10-07 변경에서 다음을 확인했습니다.

- macOS ARM 네이티브 빌드와 CTest 5/5 통과. 두 플레이어의 이미지, WAV·OGG 디코딩, 폰트 존재 검사 포함.
- 그래픽 없는 Release와 ASan·UBSan Debug 테스트 각각 4/4 통과.
- 몬스터 3종의 포획·탈출·처치, 바위 생성·충돌·수명, 음식 20종의 섞기와 습득, 생명·부활·무적 검사.
- 2인 동시 이동·점프·발사, 독립 마나·발사 대기시간, 다른 사람의 포획 거품 터뜨리기, 습득자에게만 점수 지급, 비활성·탈락 플레이어 제외, 2→1→2 재시작 검사.
- 다섯 라운드의 적 수와 진행·승리, 마지막 생명과 클리어가 겹칠 때 잘못된 부활·승리가 발생하지 않는지 검사. 라운드 전환 단위 검사는 적 제거를 주입하며, 전체 다섯 라운드를 직접 플레이한 검증과는 구분합니다.
- 공유 거품 배열 64개 고갈과 재사용, 두 캐릭터의 전체 25개 발판 도달 검사. 적·바위·아이템을 포함한 60,000틱 결정성·유한성 검사에서 게임플레이 검사 22,341,330개 통과.
- 입력 함수 검사에서 2P Right Shift 발사, 2인 모드의 Slash·Right Ctrl 해제, 1인 별칭 유지 확인. 순위표 검사에서 플레이어별 저장, 탈락·0점 입력, 중복 저장 방지, 실패 재시도와 스모크 실행의 파일 쓰기 금지 확인.
- 실제 macOS 앱의 2인 스모크 실행 1,320프레임 / 2,640틱 완료. 몬스터 처치 후 2라운드 도달, 1P 생명 감소와 서로 다른 마나 상태를 확인했습니다. 1인 모드도 120프레임 / 240틱 실행했습니다. 메뉴·플레이·이니셜 입력·저장 실패·순위표 화면도 시각 검사했습니다.
- Windows x64 LLVM-MinGW 교차 빌드로 게임과 테스트 실행 파일 생성. PE32+ x86-64 형식, 패키지 에셋 40개의 원본 일치, 외부 C++·Raylib DLL 의존성 없음 확인.

Windows 프리셋은 Visual Studio 18 2026 생성기, C11과 x64를 사용하며 CMake 4.2 이상이 필요합니다. **이 macOS 환경에서는 VS2026 MSVC 자체의 빌드·실행을 검증하지 못했습니다.** 제공한 Windows 스크립트와 CI는 해당 환경에서 빌드·CTest·설치 에셋 검증을 수행하도록 구성되어 있습니다. 워크플로 변경만으로 원격 CI가 통과했다고 볼 수 없습니다.

게임패드 두 개의 실제 장치 입력, Windows의 그래픽·오디오·키보드 동작은 별도 장치 검증이 필요합니다. macOS 앱은 서명·공증하지 않은 로컬 개발자 번들입니다. 실행 안내는 [README](../README.md), 플랫폼 설정은 [빌드 안내](BUILD.md)를 참고하세요.
