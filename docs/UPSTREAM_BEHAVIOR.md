# 업스트림 동작 참고 자료

이 문서는 C 전환을 안내하기 위해 커밋 `6a59ee99e621f4061cab50802155b9c28c51c4f9`의 Julian Rijken BubbleBobble 소스를 감사한 결과입니다. 업스트림 구현을 설명할 뿐 C 포트가 정확히 동일한 동작을 한다고 주장하지 않습니다. 원본 C++ 작업 파일은 이 결과물 범위 밖에 있습니다. 아래 경로의 기준은 업스트림 저장소와 Git 기록입니다. C 포트에서 검증한 상태와 남은 작업은 최상위 README를 참고하세요.

포트의 애플리케이션, 게임플레이, 플랫폼 인터페이스, 테스트는 C11입니다. raylib에 번들된 GLFW의 macOS 창 백엔드도 C 지향 인터페이스를 통해 Cocoa를 호출하는 네이티브 Objective-C `.m` 파일을 포함합니다. 의존성 트리가 ISO C만으로 이루어진 것은 아니며 Objective-C와 macOS 시스템 프레임워크는 플랫폼 요구 사항으로 남습니다. 애플리케이션 C++/Objective-C++ 소스나 직접 C++ 런타임 의존성은 필요하지 않습니다. 빌드·링크 경계는 `docs/BUILD.md`를 참고하세요.

## 좌표계와 레벨 데이터

- 업스트림은 가로 32, 세로 28 타일 세계, 타일당 8픽셀, 256x224 논리 프레임버퍼, 1024x896 초기 창을 사용합니다. 세계 원점은 중앙이며 양의 Y축은 위를 향합니다. 이미지 좌표 `(x, y)`의 타일은 세계 좌표 `(x - 16, 14 - y)`에서 시작하고 충돌체 중심은 `(0.5, -0.5)`만큼 오프셋됩니다.
- `Assets/Levels.png`는 32x84픽셀이며 세로로 쌓인 32x28 레벨 3개입니다. 빨강 255는 장식 타일입니다. 그렇지 않고 초록 255이면 일방 통과 발판, 그렇지 않고 파랑 255이면 단단한 타일입니다. 나머지 픽셀은 비어 있습니다. 이 색 채널 검사 순서는 중요하며 업스트림은 알파를 검사하지 않았습니다.
- 타일 이미지는 `LevelTiles.png`이고 셀은 `(0, levelIndex)`입니다. 플레이 가능한 레벨 인덱스는 0부터 2까지입니다.
- C 코어는 왼쪽 위 원점과 아래를 향하는 양의 Y축을 사용합니다. 세계 물체 중심 `(x, y)`는 `(x + 16, 14 - y)`로 변환합니다. 물체 중심과 타일 원점을 혼동하면 안 됩니다.
- 플레이어 시작 중심 `(-12, -10)`과 `(12, -10)`은 C 위치 `(4, 24)`와 `(28, 24)`에 대응합니다.
- 일방 통과 발판은 다른 물체의 이전 바닥이 발판 상단보다 위에 있을 때만 충돌을 활성화하며, 0.05타일 오차를 허용합니다.

출처: `src/Game.h`, `src/Game.cpp::ParseMaps`, `src/Game.cpp::SpawnLevelTiles`, `src/Components/OneWayPlatform.cpp`

## 게임 진행과 모드

- 메뉴 선택지는 `1P START`, `2P START`, `VS START`, `LEADERBOARD`입니다.
- 1인 모드는 초록 플레이어 한 명을 사용합니다. 협동 모드는 초록과 파랑 플레이어를 사용합니다.
- 대전 모드는 초록 플레이어 한 명과 무작위로 선택한 Zen-Chan 또는 Maita 한 명을 플레이어 2가 조작합니다. 용 플레이어 두 명을 쓰지 않습니다. 조작하는 적은 플레이 가능한 모든 레벨에서 일반 적 등장 일정을 대체합니다.
- 스토리 인트로는 7초간 지속됩니다. 플레이어는 반지름 3.5, 초당 3라디안 속도의 큰 거품을 타고 X -6/+6, Y -3 오프셋을 둔 중심 주위를 공전합니다.
- 스테이지 전환은 4초간 지속됩니다. 살아 있는 플레이어는 거품 속에서 기본 위치로 이동합니다. 이전 스테이지는 사라지고 새 스테이지가 스크롤되어 들어옵니다.
- 적은 세계 Y 14에서 등장해 아래 표의 대상 중심을 향해 각 지연 시간 뒤 2초 동안 내려옵니다. 세 일정은 다음과 같습니다.

| 1 | Maita | (0, 6) | 1초 |

| 2 | Zen-Chan | (-4, 4) | 0초 |

- 적을 포획해도 남은 적 집합에서 제거하지 않습니다. 마지막 포획 적이 죽고 파괴된 뒤 스테이지를 클리어합니다. 다음 전환 전에는 7초간 수집 시간이 있습니다.
- 레벨 3을 클리어하면 점수 화면으로 이동합니다. 이 저장소에는 추가 플레이 가능 레벨이 구현되어 있지 않습니다.

## 플레이어 이동, 공격, 체력

주요 플레이어 상태는 걷기, 점프, 사망, 수송 거품입니다. 공격은 동시 상태이므로 발사해도 이동이 멈추지 않습니다.

| 속성 | 업스트림 값 |
| --- | --- |
| 플레이어 충돌체 | 1.80x1.95타일 |
| 걷기 속도 | 8타일/초 |
| 걷기 중 중력 배율 | 3 |
| 걷기 상태 지면 확인 유예 | 0.5초 |
| 지면 탐침 | 점프는 0.5타일, 기본 캐릭터는 0.2 |
| 점프 초기 수직 속도 | +18타일/초 |
| 점프 중력 | -30, 업스트림 물리 물체에 적용 |
| 수동 공중 수평 속도 | 4타일/초 |
| 느린 낙하 수직 속도 | -6타일/초 |
| 최소 점프 시간 상수 | 0.5초, 선언했지만 사용하지 않음 |
| 거품 발사 간격 | 0.4초 |
| 거품 발사 속도 | 20타일/초 |
| 부활 무적 시간 | 3초 |
| 초기 생명 카운터 | 3, 아래 업스트림 결함 참고 |

점프는 플레이어가 입력 방향을 반대로 바꾸거나 수평 속도가 0이 될 때까지 초기 수평 관성을 유지합니다. 그 뒤 수동 공중 제어를 활성화합니다. 느린 낙하는 정점에서 자동 시작하지 않고 점프 시작 높이보다 아래에서 시작합니다. 발판에서 떨어지면 즉시 느린 낙하로 들어갑니다. 지면 판정은 위로 움직이는 물체를 제외하고 플레이어 점프용 포획 거품도 포함합니다.

발사는 플레이어 중심 앞 2.4타일(`0.9 + 1.5`)에서 시작합니다. 타일 레이캐스트는 가까운 벽에 막힌 발사를 줄입니다. 거품을 충돌 지점에 놓고 플레이어 높이의 절반만큼 내리며 수평 발사 속도를 0으로 만듭니다. 플레이어 피해는 포획 거품, 비활성 상태, 3초 부활 보호를 무시합니다. 플레이어끼리는 충돌하지 않습니다. 적은 접촉 피해를 주는 동안 플레이어와 겹칩니다.

## 포획 거품

- 충돌체는 1.5x1.5타일이고 반발 계수 0.8, 마찰 0.5, 중력 비활성입니다.
- 처음 0.1초 동안 플레이어 충돌은 비활성입니다.
- 비어 있는 거품은 충돌 즉시 적 한 명을 포획할 수 있습니다. 적은 숨기고 거품 내부의 포획 애니메이션으로 표현합니다.
- 거품은 1초 뒤 떠오르기 시작합니다. 세계 Y 3보다 아래에서는 위쪽 힘 3을 받습니다. 모든 살아 있는 거품의 평균 위치를 향한 변위의 0.3배가 끌어당기는 힘입니다. 각 고정 틱은 [-20, 20]의 무작위 X/Y 힘과 속도 비례 항력 `-velocity`도 더합니다.
- 거품이 1초 이상 되었을 때 충돌은 `length(otherVelocity - bubbleVelocity) + bubbleAge >= 15`일 때만 파열시킵니다. 오래된 거품을 단순히 건드린다고 무조건 파열하지는 않습니다. 단단한 타일, 다른 거품, 플레이어가 모두 참여하며 거품은 일방 통과 발판 충돌체를 무시합니다.
- 파열은 거품 이동을 멈추고 0.25초짜리 두 프레임 파열 애니메이션을 재생합니다. 완료하면 포획된 적은 죽은 버전이 됩니다.
- 8초가 지나면 거품은 파열하지만 포획한 적을 살아 있는 상태로 풀어 줍니다. 풀린 Zen-Chan은 화난 상태가 되고 Maita는 별도 변경이 없습니다.

출처: `src/Components/CaptureBubble.h/.cpp`, `src/Prefabs.cpp`

## 적, 바위, 아이템

| 속성 | Zen-Chan | Maita |
| --- | --- | --- |
| 충돌체 | 1.80x1.90 | 1.80x1.90 |
| 걷기 속도 | 8 | 6 |
| 강제 낙하 속도 | 아래로 5 | 아래로 8 |
| 점프 속도 | 위로 10 | 위로 12 |
| 점프 때 유지하는 수평 관성 | 0.2 | 0.5 |
| 위쪽 발판 탐색 높이 | 5 | 5 |
| 플레이어 조작 공격 | 화난 상태 전환 | 바위 던지기 |
| 화난 상태 이동 배율 | 1.8 | 구현하지 않음 |
| 처치 아이템 | 수박, 100점 | 감자튀김, 200점 |

- AI는 무작위 방향을 향해 시작합니다. 벽 전환을 위해 타일과 적을 탐침하고 전환 쿨다운은 1초입니다. 위쪽에 발판이 있고 플레이어가 1타일 이상 높으며 이동이 그 플레이어를 향하고 1~1.5초 점프 간격이 지나면 가장 가까운 플레이어 쪽으로 점프하려고 합니다.
- 의도한 목표 바라보기 간격은 2~3.5초입니다. 아래 소스 문제를 참고하세요.
- Maita의 자체 공격 쿨다운은 4초이고 AI는 5초마다 공격을 시도합니다. 바위 속도는 15이며 수평에서 0.5라디안 이내의 무작위 각도를 사용하고 바라보는 방향에 맞춰 조정합니다. 바위는 3초간 존재하고 1.5x1.5 충돌체, 반발 계수 0.9를 가지며 접촉 시 플레이어에게 피해를 줍니다.
- 패배한 적 물체는 50~70도 무작위 각도로 크기 15~20의 속도를 받고 필요에 따라 90도를 더합니다. 업스트림은 이를 충격량으로 적용하므로 정확한 결과 속도는 기존 물리 물체 질량에 따라 달라집니다.
- 죽은 적은 유효한 튀김이 3회보다 많아지면 아이템이 되며, 각 카운트 사이에는 최소 0.5초가 있습니다. 즉 4번 튑니다.
- 아이템은 아래로 9타일/초 이동하고 타일과 충돌하며 10초 뒤 사라집니다. 살아 있는 플레이어가 수집할 때만 점수를 줍니다. 파열 자체는 점수를 주지 않습니다. 색이 있는 점수 라벨은 2초 동안 4타일 떠오릅니다.

플레이어 애니메이션 프레임은 다음과 같습니다.

- 대기: `(0,0),(1,0)`, 7fps
- 걷기: 0~3열, 0행, 7fps
- 점프: 0~3열, 1행, 4fps
- 낙하: `(2,1),(3,1)`, 4fps
- 공격: `(0,2)`, 6fps, 한 번 재생
- InBubble: `(1,2),(2,2)`, 4fps
- 사망: 3행의 `0,1,2,3,0,1,2,3,4,5,6`열, 10fps. 마지막 열은 이미지 밖이므로 포트는 아틀라스 밖을 읽지 않도록 안전하게 처리해야 합니다. 유효한 사망 프레임 셀은 5열까지입니다.

공격 거품은 생성 시 0~3열을 12fps로, 대기는 3·4열을 12fps로, 파열은 5·6열을 8fps로 사용합니다. 큰 거품은 생성 0·1·2열을 4fps로, 대기 3·4열을 4fps로, 파열은 5·6열을 8번 번갈아 쓴 뒤 7·8열을 12fps로 사용합니다. 숨김은 8열입니다. 파티클 애니메이션은 0~3열을 4fps로 사용합니다.

적 애니메이션은 Zen-Chan은 0행, Maita는 1행을 사용합니다. 일반 0·1열, 포획 6·7열, 사망 12~15열은 모두 4fps입니다. Zen-Chan의 화난 상태는 2·3열입니다. 적 그림은 기본적으로 왼쪽을 향하고 플레이어 그림은 오른쪽을 향합니다. 바위는 2행의 `5,4,3,2,1,0`열을 4fps로 사용합니다. 수박은 아이템 셀 `(19,0)`, 감자튀김은 `(25,0)`입니다.

원본 게임에서 연결한 소리 파일은 음악 `SFX/The Quest Begins.ogg`, 발사 `SFX/Bubble Bobble SFX (2).wav`, 사망 `SFX/Bubble Bobble SFX (3).wav`, 점프 `SFX/Jump.wav` 네 개뿐입니다. 글꼴은 크기 8의 `NES_Font.ttf`입니다. 다른 에셋은 보존하지만 추가 구현 게임플레이의 증거는 아닙니다.

## 입력과 영구 점수

- 키보드 이동: A/D 또는 왼쪽/오른쪽. 점프: Space, W, X 또는 위쪽. 공격: E 또는 Z.
- 게임패드 이동: D-pad 또는 왼쪽 아날로그 X. 점프: B 또는 D-pad 위쪽. 공격: A.
- 1인 모드에서 키보드와 게임패드 0은 초록을 조작합니다. 원본 협동 모드에서는 게임패드 0이 초록을, 키보드와 게임패드 1이 파랑을 조작합니다. 대전에서는 키보드와 게임패드 0이 초록을, 게임패드 1이 적을 조작합니다. 포트는 두 키보드 배치를 문서화한 접근성 개선으로 제공할 수 있습니다.
- UI 선택: E, Enter 또는 Space / 게임패드 A. 위: 위쪽, X 또는 W. 아래: 아래쪽, Z 또는 S.
- M은 소리를 전환합니다. Escape/F3은 초기화, F1/P는 레벨 진행, F2는 점수 화면을 엽니다. 대괄호는 시간 배율을 바꿉니다. 이는 원본 디버그 단축키입니다.
- 점수는 `./Scores/Scores.txt`에 한 줄당 `score round initials` 레코드 하나로 저장합니다. 원본 쓰기는 레코드를 추가합니다. 정렬은 내림차순 점수, 내림차순 라운드입니다. 이니셜은 A~Z에서 선택한 세 글자입니다.
- 순위표 메뉴는 상위 10개를 표시합니다. 게임 종료 입력은 상위 5개를 표시하고 초록 플레이어 이니셜 뒤 파랑 플레이어 이니셜을 입력받으며 각 점수를 별도로 씁니다. 대전에는 적 플레이어의 점수 획득 경로가 없습니다.
- 점수 상태는 -1에서 시작해 첫 점수 획득 때만 0이 됩니다. 한 번도 점수를 얻지 못한 플레이어는 이니셜 입력 대상으로 제시하지 않습니다. HUD는 그래도 0을 표시합니다.

## 그대로 복사하면 안 되는 업스트림 문제

아래는 원본 소스의 관찰 사항이며 새 포트 회귀가 아닙니다. 의도한 동작을 정하고 의도적으로 고친 내용은 기록해야 합니다.

1. 플레이어 사망 애니메이션은 6열 아틀라스에서 6열을 참조합니다.
2. `Health::Damage`는 카운터가 0보다 작을 때만 최종 사망으로 선언합니다. 시작값 3은 결과적으로 4회 피격을 허용합니다. 최종 사망 이벤트를 듣는 게임 소스가 없고 마지막 사망 상태는 부활하지 않습니다. 해당 소스의 자동 게임 오버 진행은 불완전합니다.
3. 적 AI는 `m_TargetDirection.length() > 5`를 검사합니다. GLM 벡터의 `length()`는 벡터 크기가 아니라 구성 요소 수를 반환합니다. 이 조건은 의도한 거리 검사를 표현할 수 없으므로 고치려면 기하학적 길이를 사용해야 합니다.
4. `UserScore::operator>`는 이름을 자기 자신과 비교하는 `return name > name`으로 끝납니다. 같은 점수·라운드에 효과적인 이름 동점 해소가 없습니다.
5. 이니셜 확인은 파랑 플레이어가 이니셜을 입력할 때도 초록 플레이어의 텍스트 렌더러를 검사하며 그 단계에서 마침표를 허용할 수 있습니다.
6. 새로 만든 빈 점수 파일은 읽는 중 예외를 던지고 UI는 이를 빈 순위표로 처리합니다. C 구현은 빈 파일을 정상 상태로 처리하고 실제 파일 시스템 오류와 구분해야 합니다.
7. 맵 주석은 파일을 JPEG XL이라고 하지만 실제로 읽는 에셋은 PNG입니다.
8. 디버그 시간 배율 감소는 잘못된/음수 값까지 갈 수 있습니다. 프로덕션 시뮬레이션 단계는 그 결함을 재현하지 말고 명시적인 범위를 둬야 합니다.

이는 통과했다고 주장하는 목록이 아니라 검증 목록입니다. 검사한 플랫폼과 빌드를 포함해 포트의 검증 기록에 결과를 표시하세요.

- [ ] PNG 맵 3개를 올바른 방향, 타일 행, 단단함으로 렌더링한다.
- [ ] 플레이어 스프라이트가 이동 방향을 올바르게 향하고 모든 애니메이션 소스 셀이 유효하다.
- [ ] 1인, 협동, 대전을 시작·재시작하고 올바른 점수 흐름에 도달한다.
- [ ] 협동 플레이어 두 명이 동시에 동작하고 대전은 적 종류를 조작한다.
- [ ] 점프가 아래에서 일방 통과 발판을 지나고 위에서 착지한다.
- [ ] 점프 관성, 느린 낙하 기준, 거품 탑승, 공중 제어를 검사한다.
- [ ] 발사는 쿨다운을 지키고 벽 옆에서도 가능하며 모든 적 종류를 포획한다.
