## 완료한 범위

업스트림 `6a59ee99e621f4061cab50802155b9c28c51c4f9`에는 C++ Julgen 엔진에 연결된 약 4,056줄의 C++ 구현과 헤더가 있었습니다. 실행 C++ 소스와 서브모듈은 제거했습니다. 애플리케이션 C 번역 단위가 플레이 가능한 초기 포트를 제공하고, C 파일 3개가 게임플레이·플랫폼·레거시 오디오 디코더를 검사합니다. 원본 코드는 실행 소스에 포함하거나 배포하지 않으며 Git 기록에서 복구할 수 있습니다.

게임 루프와 원본 스테이지 3개를 1인, 협동, 대전 모드로 구현했습니다. 에셋 파일 40개는 업스트림과 정확히 같습니다. 원본 게임플레이 상수와 알려진 업스트림 결함은 [UPSTREAM_BEHAVIOR.md](UPSTREAM_BEHAVIOR.md)에 기록했습니다.

Windows 바이너리는 LLVM-MinGW `20260908`, Clang 23, UCRT로 빌드했습니다. 애플리케이션이나 의존성 구성에서 C++ 컴파일러를 선택하지 않습니다. Raylib는 정적입니다. macOS의 의존성·애플리케이션 컴파일 단위 37개에는 Cocoa용 Objective-C `.m` 파일 5개가 포함되며 `.cpp`나 `.mm` 입력은 없습니다.

고정한 의존성은 최신 Clang에서 기존 `stb_vorbis` 포인터 비교 경고를 냅니다. CMake는 raylib의 오래된 최소 정책 선언과 Apple의 사용 중단된 OpenGL 프레임워크도 보고합니다. 프로젝트 C 소스는 `-Wall -Wextra -Wpedantic -Werror`를 통과하며, 의존성 경고는 숨기지 않고 기록합니다.

## 남은 작업과 우선순위

1. **Windows 두 아키텍처를 Windows에서 실행합니다.** 제공한 MSVC 프리셋으로 CTest를 실행하고 패키지 게임을 실행합니다. 디스플레이 배율, 창 크기 조절/전체 화면, 키보드·게임패드 핫플러그, 오디오 장치 손실, 비ASCII 설치·저장 경로를 검사합니다. 교차 컴파일은 코드 생성과 링크만 증명하며 장치 동작은 증명하지 않습니다. OpenGL 3.3 그래픽이 동작하는 Windows 10/11이 데스크톱 검증 기준입니다.
2. **업스트림 녹화와 이동·접촉 동작을 비교합니다.** C 타일 해석기는 Box2D를 대체하므로 관성, 적 등반, 튀김 충격량, 일방 통과 접촉, 거품 탑승은 근사값입니다. 거품끼리의 물리 충돌과 플레이어 이외 힘 기반 파열은 단순화되어 있습니다. 이것이 게임 충실도에서 가장 큰 차단 요인입니다.
3. **전환과 효과 연출을 마무리합니다.** 4초 스크롤·거품 수송 스테이지 전환, 원본 인트로 궤도·스토리, 거품 나선, 상태별 죽음·점프·파열 애니메이션 타이밍, 떠오르는 점수 텍스트를 복원합니다. 현재 7초 인트로/클리어 타이밍의 연출은 단순화했습니다. 적 드롭은 수집 시간을 놓치지 않도록 4초 보정값을 유지합니다.
4. **전체 플레이와 컨트롤러 인수 검사를 완료합니다.** 1인/협동/대전에서 맵 3개를 사람이 직접 플레이하고, 모든 생명 소진과 이니셜 입력·저장·재실행을 확인합니다. 물리 게임패드 2개를 시험합니다. 현재는 바인딩과 시뮬레이션 코어 동작만 검증했습니다. 결정적 픽스처에서 추론하지 말고 실제 맵으로 장시간 동작을 확인합니다.
5. **그 검증 뒤 릴리스 패키지를 준비합니다.** 현재 Windows 출력은 콘솔 실행 파일이고 macOS 앱은 서명되지 않은 로컬 개발자 번들입니다. 설치 관리자, 서명/공증, 릴리스 자동화 결과, 프로덕션 준비 완료 주장은 없습니다. 같은 점수 파일을 동시에 쓰는 프로세스는 조정하지 않으므로 마지막 성공 저장이 남습니다. 파일 교체는 검사했으나 충돌·정전 내구성을 보장하지 않습니다.

## 업스트림에서 의도적으로 바꾼 점

- 표시한 시작 생명 3개는 이제 3회 피격을 뜻합니다. 업스트림은 0 아래로 감소한 뒤 죽음으로 판단했고 마지막 플레이어 사망 뒤 게임을 자연스럽게 끝내지 못했습니다.
- 점수 0은 업스트림의 `-1` 감시값 대신 0에서 시작하므로 0점 게임도 이니셜 입력을 할 수 있습니다.
- 두 플레이어 모두 키보드를 사용할 수 있습니다. 업스트림 협동은 플레이어 1에 컨트롤러를 요구했습니다.
- 표준 C 타일 해석기와 크기 제한 풀은 엔진 객체, 컴포넌트, 이벤트, RTTI, 스마트 포인터, 물리 콜백을 대체합니다. 풀 용량을 넘기면 플레이 중 재할당하지 않고 새 엔티티 생성을 거부합니다.
- 점수는 크기를 제한하고 검증하며 저장소 대신 사용자별 위치에 저장합니다. 지나치게 긴 잘못된 행은 건너뛰고 읽기 실패 시 그 세션의 영구 저장을 비활성화합니다.
- 알려진 업스트림의 잘못된 죽음 프레임 인덱싱과 벡터 길이 AI 오류는 재현하지 않습니다.
